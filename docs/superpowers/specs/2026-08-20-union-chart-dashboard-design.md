# Union Watchlist Chart Dashboard — Design

Date: 2026-08-20

## Purpose

The EMA55 union watchlist (`ema55_cross_scans/ema55_cross_scans.md`) already lists
~400-500 symbols each day, sectioned by confluence tier (ALL 4 / 3 OF 4 / 2 OF 4 /
1 ONLY), but only as a comma-separated TradingView-paste block and a metrics table
limited to the ~420 symbols EMA55 itself scanned. There's no way to actually see
price action — candles, volume, EMAs — without pasting into TradingView symbol by
symbol. This adds a self-contained HTML dashboard that plots every union symbol as
an interactive candlestick+volume chart, with live (client-side) controls to
recolor candles and change EMA overlay periods, refreshed daily after market close
alongside the rest of the pipeline.

## Pipeline wiring

New script `union_chart_dashboard.py`, run immediately after
`run_ema55_cross_scanner.ps1` in `run_all_scanners.ps1` (needs today's union block
already written). New PS1 runner `run_union_chart_dashboard.ps1`, same shape as
`run_ema55_cross_scanner.ps1` (log to `logs/`, run script, git add+commit+push).

```
Run-Scanner "EMA55_Cross"           "$ROOT\run_ema55_cross_scanner.ps1"
Run-Scanner "UnionChartDashboard"   "$ROOT\run_union_chart_dashboard.ps1"
```

## Symbol source

Reuse `ema55_cross_scanner._symbols_from_tv_block` and `_load_union_source`
against `ema55_cross_scans/ema55_cross_scans.md` (import, not reimplement — same
decoupled "read the other scanner's already-written md" convention the union
section itself already uses). Freshness check identical to that module's own:
today's title-date must match `TODAY`, else abort the run with a logged reason
and write nothing (no stale publish — matches
`.claude/rules/backtesting-integrity.md`'s scanner-output-integrity rule).

The full union set (all 4 tiers) is charted — not just EMA55's own ~420-row
findings — since the point is seeing price action for every union symbol,
including the ~80 flagged only by EMA25 ZL / Minervini / Trend Scanner.

## Data

`load_ohlc_many(symbols, lookback=250)` from `ohlc_db.py` — the only DB entry
point, per `scanner-conventions.md`. 250 daily bars covers EMA200 warmup with
headroom and ~10 months of chart history. Symbols returning fewer than 130 bars
(new listings, same warmup floor `ema55_cross_scanner.analyse()` uses) are
skipped from the chart set; the count skipped is logged, not silently dropped
(`Workflow`-style "no silent caps" spirit, and this repo's own convention of
writing `*No signals.*` rather than an empty section applies analogously here).

No server-side EMA computation — each symbol's data ships as a plain OHLCV array;
EMA lines are computed client-side in JS so the live period-input control can
recompute instantly without a page regenerate.

Per-symbol JSON shape:
```json
{"symbol": "RELIANCE", "tier": "ALL 4", "bars": [["2025-10-01", 2450.0, 2470.0, 2440.0, 2465.0, 3200000], ...]}
```
(`bars` = `[date, open, high, low, close, volume]`, oldest first — same order
`load_ohlc_many` already returns.)

## Chart tech

Vendor `lightweight-charts.js` (TradingView's OSS charting library — candlestick
series, volume histogram pane, and line series for EMA overlays all built in,
~45KB minified) as a single committed file at `dashboard/vendor/lightweight-charts.js`.
Vendored rather than CDN-linked: this page is generated by an unattended scheduled
task, and a CDN outage shouldn't break a daily-refreshed historical dashboard.
Vendoring is a one-time manual step (download once, commit); it is not
re-fetched by the daily script.

Output: `dashboard/union_charts.html`, single file, referencing the vendored JS
via a relative `<script src="vendor/lightweight-charts.js">` and embedding all
symbols' data inline as one JSON blob (`<script>const CHART_DATA = {...}</script>`).

### Layout

Grid of cards (`display:grid; grid-template-columns:repeat(auto-fill,minmax(320px,1fr))`),
one per symbol, each showing:
- Symbol name + TradingView link + confluence tier badge (color matches the tier,
  same visual language as the existing union markdown section)
- A `lightweight-charts` instance: candlestick series + volume histogram pane

At ~500 cards, constructing all chart instances on load stalls first paint.
Mitigation: `IntersectionObserver` per card — a chart is only constructed
(`LightweightCharts.createChart(...)` + data set) the first time its card
scrolls into the viewport. Off-screen cards stay as empty placeholders until
then. This is required for usability at this scale, not speculative
gold-plating.

### Global controls

One control bar pinned above the grid:
- Up-candle color picker, down-candle color picker (native `<input type=color>`)
- EMA periods text input, default `20,50,200` (comma-separated ints)
- Symbol/tier filter text input (substring match, same pattern as
  `dashboard/footprint.html`'s existing filter box)

Changing color or EMA periods re-applies to every **already-constructed** chart
immediately (candle series `applyOptions`, EMA line series removed/recreated from
the same client-side-computed data — no data re-fetch, no page reload) and is
also applied to any chart constructed later (lazily, on scroll) via the same
current control state. No persistence needed (repo convention: dashboards are
regenerated fresh each day, no localStorage precedent in `footprint.html` or
`breadth.html` either — matches existing pattern, not scope creep).

### EMA calculation (client-side JS)

Standard EMA: `ema[i] = close[i] * k + ema[i-1] * (1-k)`, `k = 2/(period+1)`,
seeded with the first `period` closes' SMA — mirrors
`ema25_zl_scanner.ema()`'s pandas `.ewm(span=n, adjust=False)` formula (same
math, different runtime), satisfying `pine-script-conventions.md`'s
Python-parity spirit even though this isn't Pine.

## Output & disclaimer

`dashboard/union_charts.html` gets `SEBI_HTML_BANNER` after `<body>` and
`SEBI_HTML_FOOTER` before `</body>`, per this repo's CLAUDE.md mandatory-disclaimer
rule. Committed as a data-only commit: `[scan YYYY-MM-DD] union charts: N symbols`.

## Testing

New `tests/test_union_chart_dashboard.py`:
- Symbol-source freshness check (stale/missing union md → abort, nothing written) —
  mirrors the existing `_load_union_source` staleness tests in
  `test_ema55_cross_scanner.py`
- OHLCV JSON-builder round-trips a fixture DataFrame correctly (dates as
  `YYYY-MM-DD` strings, correct column order, correct row count)
- Bars-floor skip: symbol with <130 rows is excluded, skip count reported

No live OHLC/network dependency needed — same pattern as the repo's other
pure-function unit tests. Client-side JS (EMA calc, lazy-init, control
re-apply) has no automated test (no JS test runner in this repo's stack); a
manual check is opening the file in a browser and confirming: charts render as
cards scroll into view, changing EMA periods updates visible lines, changing
candle colors updates visible candles.
